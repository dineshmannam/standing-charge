# Decisions

Why, not what. The what is visible in the code. The why evaporates in a month
and is the only part worth reading later.

`findings.md` records what the world turned out to be. This records what we
chose and what we rejected.

| Date | Decision | Why | Rejected |
|---|---|---|---|
| 2026-09-01 | Pivot from GPU inference to Cloud Run | L4 quota refused: project too new, billing account had no history. Cloud Run has the same idle-versus-per-request economics with no quota gate. | Waiting for quota. Switching to a codelab with no cost tension. |
| 2026-09-01 | Keep the GPU project parked, not cancelled | Resubmit for 4 GPUs Thursday. If it lands, every tool built here still works and the GPU run becomes a second, bigger video. | Abandoning it. |
| 2026-09-01 | One GCP project per lever | Vertex bills at project level with no resource to label. The project is the only attribution boundary that works. | Single project with time-boxed runs. Too fragile. |
| 2026-09-01 | Enable FOCUS and detailed exports both | FOCUS is Preview. The run is unrepeatable. Redundancy costs nothing. | FOCUS alone. |
| 2026-09-01 | Freeze traffic profiles before the first run | Changing the workload between runs makes the comparison meaningless and cannot be fixed afterward. | Tuning profiles as results came in. |
| 2026-09-01 | steady and bursty matched on total volume | First draft had bursty sending 2x the requests. Any cost difference would have been traffic, not shape. Caught by testing the schedule generator rather than reading it. | Leaving them unmatched. |
| 2026-09-01 | Preflight before any spend | Quota, version and permission problems have multi-day lead times. Found the GPU blocker four days early. | Discovering problems on film day. |
| 2026-09-02 | Film day separate from reveal day | Billing export lags roughly a day. A genuine first reaction to real numbers cannot be reshot. | Filming the reveal from data seen the day before. |
| 2026-09-02 | 2560x1440 at 30fps, clamshell, external display | Terminal text goes mushy at 1080p on a phone. 4K costs storage and export time for no gain on monospace. No motion that benefits from 60fps. Clamshell removes the notch and the second display. | 1080p60. 4K30. Recording the laptop panel. |
| 2026-09-02 | `CLOUDSDK_CORE_DISABLE_PROMPTS=1` in every script | gcloud prompts "enable API? (y/N)" on stdin and waits forever. Hung preflight for 6 minutes with no output. A check script that can block on input is broken by design. | Assuming APIs would always be enabled. |
| 2026-09-02 | Missing APIs are a hard exit, not a warning | Every check after the API section depends on them. Warning and continuing produced a cascade of confusing 403s instead of one clear instruction. | Warn and carry on. |
| 2026-09-02 | Discover the FOCUS dataset name, never guess it | Google created it as `..._CDEF01_us`, lowercase. The hardcoded guess was wrong. The suffix depends on the export location chosen at setup and is permanent. | Hardcoding `_US`. |
| 2026-09-02 | Identity values hardcoded in env.sh, not `${VAR:-default}` | A stale `PROJECT_NAME` export from a previous project silently won and got written into resource labels. | Defaults with fallback. |
| 2026-09-02 | Run id lives in a file, not a variable | Same class of bug. Four panes open on film day, and a run id that differs between them would only surface in the billing data days later. | Exporting it per shell. |
| 2026-09-02 | Lever isolation checked against configured project vars, not name patterns | Name heuristics warn on correct setups and miss wrong ones. Comparing `PROJECT_ID` to `PROJECT_LEVER_$LEVER` catches the real failure: a stale shell pointing at the wrong project. | Matching substrings like `lever-a` or `idle`. |
| 2026-09-02 | Every gcloud call carries `--project="$PROJECT_ID"` | `gcloud run deploy` has no implicit project binding and fell back to `gcloud config`, deploying to the `gcloud config` project while env vars said `sc-lever-a-idle`. | Relying on `gcloud config set project`. |
| 2026-09-02 | `CLOUDSDK_CORE_PROJECT` exported from env.sh | Belt and braces. Makes the gcloud default follow the active lever, so a command that forgets the flag still lands correctly. | Flag discipline alone. |
| 2026-09-02 | Grant the default compute SA its Cloud Build roles explicitly | Google stopped granting Editor to `PROJECT_NUMBER-compute@developer` on new projects. Source deploys fail with an opaque storage 403 until `storage.objectViewer`, `artifactregistry.writer` and `logging.logWriter` are granted. | Assuming new projects work out of the box. |
| 2026-09-02 | Preflight checks service account permissions, not just the caller's | Two consecutive deploy failures were both service-account IAM. The script checked my permissions thoroughly and never checked the accounts that actually do the work. | Only `testIamPermissions` for the human. |
| 2026-09-02 | Create the Artifact Registry repo explicitly with labels | Source deploy auto-creates `cloud-run-source-deploy` unlabelled, so its cost is unattributable. | Letting it autocreate. |
| 2026-09-02 | Added `postflight.sh` | Preflight asks "can I run", teardown asks "did I stop paying". Nothing asked "did the run produce what I need". A silently failed sweep would have surfaced on Sunday with the camera rolling. | Checking evidence by eye. |
| 2026-09-02 | Pin `google-adk==X.Y.Z` in requirements.txt | An upgrade between lever A and lever B would confound the comparison and nothing in the data would show it. | Floating version. |
| 2026-09-02 | Deploy from the agent root with `--source "$AGENT_DIR"` | `--source .` from the repo root uploads preflight, evidence and queries to Cloud Build, which then finds no buildpack. requirements.txt must sit at the agent root, package in a subdirectory. | `--source .`. |
| 2026-09-02 | Use a GA model, not `gemini-3-flash-preview` | Preview models often have no published list price, and the entire comparison rests on having one. Settled on gemini-2.5-flash. | Following the codelab's model choice. |
| 2026-09-02 | Stay on the token route rather than fighting org policy | `--allow-unauthenticated` was refused by domain-restricted sharing. An unauthenticated agent endpoint is an unmetered one, which is a bad default in a project about cost. loadgen already attaches an identity token. | Requesting a policy exception. |
| 2026-09-02 | Capture `thoughtsTokenCount`, use `totalTokenCount` for cost | Gemini bills reasoning tokens that never appear in the response text, at the output rate. Measured at 69.6% of the billed total. Summing the visible parts undercut by 3.4x. | Summing prompt + completion. |
| 2026-09-02 | Preflight runs `py_compile` on the agent source | A stray `EOF` from a pasted heredoc surfaced as `NameError: name 'EOF' is not defined` after 30 lines of framework traceback. Preflight grepped for `root_agent` but never checked the file parses. | Trusting a grep as a syntax check. |
| 2026-09-02 | Absolute scheduling in loadgen, not sleep-between-requests | Sleeping made each cycle gap plus latency. Warm arms would send more requests per hour than cold arms, so the two curve arms would have had different traffic volumes. The tool was introducing the bias it exists to detect. | Cumulative sleeps. |
| 2026-09-02 | `--wait-for-cold` idles 15 min before min-instances=0 runs | A curl smoke test warmed the service and the first filmdemo run showed no cold start at all. Cloud Run scales to zero after roughly 15 minutes idle. | Assuming an idle-looking service is cold. |
| 2026-09-02 | loadgen writes its own wallclock rows | Six runs on Thursday means twelve manual `mark` calls, and one missed pair is a run that cannot be time-bounded. Cost queries filter on exact UTC bounds because the projects are reused. | Relying on calling `mark` by hand. |
| 2026-09-02 | Explicit BigQuery schema with `--null_marker=NA` | Token columns contain `NA` on failed requests, so `--autodetect` infers STRING and every downstream `SUM()` silently breaks. Pre-fix and post-fix CSVs also have different column counts. | `bq load --autodetect`. |
| 2026-09-02 | Cost queries bound by TIMESTAMP, not DATE | Projects are reused and carry prior spend, so a whole-day filter sweeps in unrelated cost. | Filtering on `DATE(usage_start_time)`. |
| 2026-09-02 | `filmdemo` excluded from every analysis query | Camera-only profile. Its run ids would otherwise pollute lever A's numbers. | Filtering by hand at analysis time. |
| 2026-09-02 | `cold_hint` stays a weak proxy, thresholds not tuned | Latency spread on identical requests was 4.2x with no cold start; the cold start itself was 2.35x. The effect is smaller than the noise. Lowering the threshold until request 6 tripped would have been fitting the detector to the data. Cold starts come from `run.googleapis.com/container/startup_latencies` instead. | Tuning the multiple or window until the expected requests flagged. |
| 2026-09-02 | `cold_hint` marks request 0 as `first` unconditionally | The ratio rule needs history, so request 0 could never be flagged, and that is exactly where cold starts live. | Leaving request 0 blank. |
| 2026-09-02 | env.sh derives BILLING_ACCOUNT and exports DETAILED_TABLE / FOCUS_TABLE | The Standing Charge env.sh never set them, so `postflight --billing` warned instead of running the gate query. BigQuery table names cannot contain hyphens, so the account id needs an underscore form: `012345-6789AB-CDEF01` becomes `..._012345_6789AB_CDEF01`. Building that string in three places invited a typo. | Rebuilding table names in each script. |
| 2026-09-02 | Billing account cached in evidence/billing-account | env.sh is sourced in four panes on film day and the gcloud lookup is slow. Delete the file to refresh. | A gcloud call per source. |
| 2026-09-02 | FOCUS discovery uses plain `bq ls`, not JSON plus jq | A missing jq would silently produce an empty dataset name, and an empty FOCUS_TABLE is easy not to notice until a query fails. | jq parsing. |
| 2026-09-02 | `row_count`, never `rows`, as a column alias | `rows` is reserved in BigQuery for window frame clauses. `COUNT(*) AS rows` fails with "Unexpected keyword ROWS" and a character offset that points nowhere useful. | The obvious alias. |
| 2026-09-02 | Check the bq exit code, not whether output appeared | postflight reported "billing rows found" on a query that had failed, because the error text was written to stdout and the check was `[[ -n "$OUT" ]]`. Any query failure would have looked like success. Third instance of the same blind spot: existence is not correctness. | Treating non-empty output as success. |
| 2026-09-02 | Lead the video with the token finding, land on the method | The dry run findings are stronger than the planned levers, but reasoning tokens are a Gemini implementation detail Google can change. The levers are structural and exist on every platform. Hook with the surprise, pay off with the transferable method, so the piece survives the number going stale. | Building the whole video on the finding. Burying the finding at 6:00. |
| 2026-09-02 | Three openers shot Saturday, chosen Sunday | The opener depends on whether the 6x spread survives n=120, which is not known until after filming. Ninety seconds each is cheap insurance against writing a cheque the data cannot cash. | Committing to an opener before the data exists. |
| 2026-09-02 | Report the codelab typo before filming, mention it as a correction | Publishing a video about someone's material while sitting on an unreported bug in it is the wrong order. Filing first costs ten minutes and makes the on-camera mention honest. If the report is not filed by Saturday, the beat gets cut rather than softened. | Mentioning it on camera without filing. Not mentioning it at all. |
| 2026-09-03 | Cost model uses total_tokens at the published output rate | Confirmed against Google's own pricing page: the Gemini 2.5 Flash row is named "Text output (response and reasoning)", $2.50/1M, with no separate reasoning tier. Input is $0.30/1M. Applying these to the filmdemo run: $1.02 per 1k invocations actual against $0.24 counting only visible output, a 4.3x understatement. | Treating reasoning tokens as a separate or discounted line. |
| 2026-09-03 | Identity token refreshes mid-run, retries once on 401 | `gcloud auth print-identity-token` lasts about an hour and loadgen fetched it once at startup. A 60 minute profile sits on that boundary; the steady min0 run lost its last two requests. The test duration and the credential lifetime were the same number. | Fetching once and hoping. |
| 2026-09-03 | Run loadgen under `caffeinate -dimsu` | **Confirmed root cause of the 401s.** The machine slept for 368s mid-run, drifting the schedule past the token's one hour expiry. Without the sleep the last request would have landed ~30s inside the window. A sleeping machine produces a silent hole: no error, no retry, just an absence visible only as drift. | Trusting the Mac to stay awake for an unattended hour. |
| 2026-09-03 | Separate "code taken" from "ideas taken" in attribution | Only the Cloud Run guide supplied code, roughly forty lines of agent scaffold. Levers B and C borrowed questions from two other codelabs but no implementation. Attributing broadly to "the codelabs" overclaims a relationship with material never used; saying nothing understates the one real debt. Added ATTRIBUTION.md. | A single blanket attribution line. |
| 2026-09-04 | `source env.sh B` takes the lever as an argument | `LEVER=B source env.sh` does not reliably pass the variable to a sourced file in zsh. It fails silently: `scenv` still shows lever A while you believe you switched, which would put lever B's spend in lever A's project. | Relying on the assignment prefix. |
| 2026-09-04 | Lever B pinned to exactly one instance | ADK's default session service is in-memory, so a `--same-session` run cannot survive a second or replacement instance. The first attempt lost 116 of 120 requests to 404 after the session's instance went away. `--min-instances=1 --max-instances=1` on both runs removes the confound: lever B compares compaction on against off, not hosting configurations. | Running lever B at min-instances=0 like lever A. Switching to a persistent session service, which changes what is being measured. |
| 2026-09-04 | Lever B hosting cost not comparable to lever A | Lever A swept min-instances; lever B is pinned at one. Stated as a caveat rather than silently compared. | Presenting one cost-per-1k table across all three levers without qualification. |
| 2026-09-04 | Agent Runtime checks use `gcloud beta ai`, with a REST fallback | `gcloud beta aiplatform` does not exist; the surface is `gcloud beta ai`. preflight's lever C check swallowed the invalid-command error and reported "could not list reasoning engines", which reads as absence rather than a wrong command. An unrecognised command and an empty list look identical to a bare success check. | Trusting a single gcloud invocation to distinguish "none" from "wrong command". |
| 2026-09-04 | loadgen rejects a non-URL `--url` immediately | An empty `$CLOUD_RUN_URL` produced a ValueError deep in urllib after the wallclock start row was already written. One line of validation turns a stack trace into a sentence. | Letting urllib report it. |
| 2026-09-04 | Did not set `--session_service_uri` for lever B | ADK documents `agentengine://`, `sqlite://` and `memory://` session services. Switching to a persistent one would change what lever B measures: sessions become storage operations rather than RAM, a different cost profile. Pinning to one instance holds the variable constant instead. | Fixing the session problem properly and quietly changing the experiment. |
| 2026-09-04 | loadgen gained a second invocation mode rather than a flag | Agent Engine has no service URL, no `/run`, a different token kind, session creation via a class method, and a streaming-only query surface. Supporting it meant a second client, not a parameter. `--url` and `--engine` are mutually exclusive with explicit errors. | Trying to bend the Cloud Run path to fit. |
| 2026-09-04 | Token kind follows the host: identity for Cloud Run, access for Vertex | Using the wrong kind returns 401 with no indication which was expected, which is indistinguishable from an expired token. | One token type for both. |
| 2026-09-04 | Run `filmdemo` before `steady` on any new host | The Agent Engine session extraction and stream parser were written from method signatures, not from a real response. Ten requests costs five minutes to validate; being wrong on `steady` costs an hour. | Going straight to the full profile on an unverified client. |
| 2026-09-04 | Reasoning engines handled via REST only, no gcloud | Neither `gcloud beta aiplatform reasoning-engines` nor `gcloud beta ai reasoning-engines` exists. The first correction was as unverified as the original error and was only caught at teardown. preflight now calls REST, separates an empty body from an empty list from an error object, and prints the delete command for anything it finds. | Guessing a second gcloud surface after the first was wrong. |
| 2026-09-04 | Loader treats a column mismatch as failure, and loading nothing as failure | The 15-column schema predated loadgen growing to 17. It printed SKIP for all thirteen files and exited 0. Skipping sounds deliberate and success sounds fine, so an empty dataset looked like a clean run. | Skipping unknown shapes quietly. |
| 2026-09-04 | Aborted lever B start excluded by name in the loader | `load-A-steady-run-2026-09-04-b-nocompaction.csv` holds 5 rows, all status 200: the first two minutes of the lever B nocompaction run before it was killed. `evidence/wallclock.csv` records it as a `start` at 14:24:56 with no `done`. Its prompt tokens grow 47/154/261/368/475 and every row is `session_mode=same`. A growing prompt is a conversation, which is lever B by definition; every lever A request sent the same 47-token prompt with `session_mode=fresh`. That rules out lever A data whatever the filename says, and the lever A prefix is the zsh `LEVER` bug (F13) visible in a filename. Loading it would file five lever B requests under lever A. Excluded explicitly rather than deleted, so the evidence survives. **Corrected 2026-09-12:** this row previously said the file held 116 rows of 404. Those belong to the *other* failed lever B attempt (F14), the 14:48-15:48 run. loadgen builds its output name from lever, profile and run id and opens it `"w"`, so that run wrote `load-B-steady-run-2026-09-04-b-nocompaction.csv` and the successful 16:35 rerun, sharing the same run id, overwrote it in place. No 404 row survives anywhere in the published evidence. The exclusion is still right; only the reason recorded for it was wrong. | Deleting the file, or filtering it in every query. |
| 2026-09-04 | Report lever B as a null result, do not tune the threshold | Compaction never fired: both arms grew 125 vs 126 tokens per turn with no step down, a 0.74% total difference inside thinking-token noise. The conversation reached 15k tokens against a ~1M context limit. Lowering the threshold until it fired would have manufactured the expected result instead of measuring the configured one. | Adjusting compaction settings until a difference appeared. |
| 2026-09-05 | IDE pane on camera instead of a log tail | A log tail is passive. The codebase is something to point at: showing the absolute-scheduling loop or the two session paths beats describing them. It also serves the target roles better, since someone evaluating engineering learns more from thirty seconds of loadgen.py than from streaming logs. | Live log tail in the third pane. |
| 2026-09-05 | Report the FOCUS delta as a definitional difference, not a gap | The −$0.14574 delta is exactly the Cloud Run spend, and Cloud Run's `BilledCost` and `EffectiveCost` are zero while `ListCost` and `ContractedCost` carry the figure. The detailed export shows cost $0.14574 against credits −$0.14574, net zero. Free tier absorbed it. Calling this a bug would have been wrong and would not have survived scrutiny. | Publishing "FOCUS is missing Cloud Run charges". |
| 2026-09-05 | State on screen that lever A hosting costs were never paid | Cloud Run's free tier covered all 415 rows. The 166% increase between arms is a true usage difference; the dollars are what someone past the free tier would pay. The ratio stands, the absolute figures need the qualifier. | Presenting gross cost as spend. |
